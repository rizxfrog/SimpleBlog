7) 关键写入流程（Git 行为）

7.1 初始化 doc（创建 `refs/heads/main`）

输入：`space_id`、目录位置、`title`、`content_md`、`author_id`

事务内：

1. 创建 `doc_node`（`node_type='doc'`）
2. 创建 `doc`
3. 创建首个 `doc_commit`（无 parent）
4. 创建 `doc_ref`：`(doc_id, ref_name='refs/heads/main', ref_type='branch', commit_id=<init_commit>)`
5. 写入 `doc_head`：`head_ref='refs/heads/main'`

7.2 普通提交（在某分支上提交）

输入：`doc_id`、`branch_ref`、`base_commit`（客户端看到的 tip）、`title`、`content_md`、`message`

事务内：

1. 锁住分支 ref 行：`select ... from doc_ref where doc_id=:doc_id and ref_name=:branch_ref for update`
2. 校验当前 tip `== base_commit`（否则返回 non-fast-forward）
3. `insert doc_commit`（child）
4. `insert doc_commit_parent`（`child -> base_commit`, `parent_order=0`）
5. `update doc_ref set commit_id=:child_commit where doc_id=:doc_id and ref_name=:branch_ref`

7.3 合并（merge）

输入：`doc_id`、`target_ref`、`source_ref`、`merged_content_md`、`message`

约定：

1. `parent_order=0` 固定为 target tip（first parent）
2. `parent_order=1` 为 source tip

事务内：

1. 锁 target ref：`... for update`
2. 读取 target tip 与 source tip（source 可读，是否加锁取决于你的并发策略）
3. `insert doc_commit`（内容为合并后的 markdown）
4. `insert doc_commit_parent` 两行（order 0/1）
5. `update target ref` 指向 merge commit

补充：

1. 创建 tag/branch、删除 ref、force push 统一通过 `doc_ref` 更新，并走权限校验。
2. `doc_head.ref_version` 用于 UI 侧 CAS（避免多终端覆盖检出分支状态）。
